# 离线账本、恢复与迁移交接

适用首版原生 App。Codex 实现本地数据库、文件读写和自动化核对，家长在最终验收时只需操作两台真机并核对结果。业务口径见 `docs/RULES.md`，持久化和文件格式分别见 `docs/TECH_SPEC.md`、`docs/BACKUP_FORMAT.md`。本页补充落库和互通细节。

## SQLite v1 的边界

| 数据归属 | v1 落点与检查 | 导入后的结果 |
|---|---|---|
| 家庭与伙伴 | `households.id/lineage_id/timezone/domain_revision`、`child_profiles.active_pet_id`。设备生成 UUID 作实体 ID。物种与商品用配置中的固定字符串 | 保留相同家庭、血缘、昵称和选中的 fox/rabbit/cat；首次选择、切换及恢复共用一个成长账本 |
| 任务与项目 | 模板、历史版本、实例、申报、确认和纠错关联保留稳定 ID。重复计划按模板、家庭日期和序号设唯一键 | 还原发布时的标题、标准、分值、阶段和状态；到期检查与计划补齐在激活后按正常幂等流程执行 |
| 积分 | `ledger_entries` 追加保存。`accounts.balance = SUM(delta)`，空账户按零计。同一业务来源和同一原流水的冲回分别唯一。扣分日用量按当日原实扣合计 | 目标验证初始零余额、当前非负、业务键唯一、结算日和发生日；撤销后的日用量仍与原实扣吻合 |
| 购买、搭配与摆放 | 购买按原价保存。拥有项和组件关联原购买或免费来源。空间实例 ID 与场景配置键分开；免费首页的键为 `base_room`。保存空间、归一化坐标、层级、旋转、翻转和穿戴槽位 | 退款后的资产状态、现用搭配、空间内容和心愿选定价原样还原。场景中的背景树屋不产生付费空间所有权 |
| 成长与素材 | 有效成果按家庭实际日期去重。已授予阈值单独持久化。规则与目录版本须能解析对应快照。素材引用覆盖物种、阶段、当前穿戴与所有持有组件 | 原样还原已授予阶段，即使更正后有效日期不足。离线安装包能显示所有必需素材；未知 ID 返回兼容性错误，旧代可继续打开 |
| 重试与修订 | 业务命令回执与领域事务同提交，作为家庭数据导出。命令结果按原请求语义重放，拒绝同键异参。领域写成功只加一次 `domain_revision` | 恢复后再次提交历史确认命令也不会重复入账；浏览、导出、导入回执及 Demo 外观预览都不增加修订 |
| 设备控制 | 独立控制文件保存活动代指针、冻结状态、待验证导出及最近激活备份回执。平台安全存储保存分代凭据和内部恢复点密钥 | 新设备生成新身份、PIN 校验材料和恢复密钥；备份包内无这些秘密。回滚继续使用当前有效授权 |

Codex 在数据库里程碑提交 v1 实际 DDL、Drift 导出的 schema 和从合法命令创建的数据库夹具。与配置一起版本管理。每个连接启用外键。应用预设时间与 ID 的测试适配器只在隔离测试中注入。真实安装空库以零余额、免费伙伴和免费家园初始化一次。

## 同一个文件在两端得到同样结果

- 二进制头使用 `format_version`、`kdf`、`iterations`、`salt`、`cipher`、`nonce`、`payload_bytes`。salt 与 nonce 为标准 Base64。`payload_bytes` 是密文字节数，等于待加密 ZIP 的字节数。读取时先验证总长度恰等于 `8 + 4 + header_bytes + payload_bytes + 16`。
- `fixtures/migration_roundtrip.json` 内的 `codec_vector` 提供固定测试输入及输出，口令含首尾空格和组合字符。核对原始 UTF‑8、派生密钥、密文、tag 和整个容器摘要。该向量只测容器编解码层，业务导入层应拒绝其中的单元测试载荷。每次正式导出按 `BACKUP_FORMAT.md` 生成新随机值。
- 完整导入先验证认证标签，再解压和检查原始数据库字节摘要，随后核对 SQLite 结构、外键和业务关系，最后预览。对非空家庭，用户确认并成功生成内部恢复点后才切换数据代。写入新代或指针任一步中断，重新启动时能明确选择完整代。
- 自动化另外生成**业务快照**用于跨设备逐字段比较。读取家庭及所有业务表，保留稳定 ID、历史版本、状态、命令回执和所有账本明细。每张表按主键稳定排序，嵌套对象按键排序，列表遵循业务顺序。用同一份共享 Dart 编码器产生 UTF‑8 JSON 和 SHA-256；差异报告提供表名、行 ID 和字段。控制文件、设备身份、安全存储及本机导入审计单独核对。SQLite 文件摘要校验传输，业务快照核对激活后的语义一致性。
- 冻结包括系统自动生成、到期处理、装扮、购买、家长批改等所有领域写入。保存结果未知时源端持续只读；家长回读实际文件且匹配本次待导出 backup_id、家系、修订和认证后的数据库摘要，才可标记文件已核实。源端可重新保存同一份已验证快照；目标不会向源设备发送联网回执。
- 最近激活回执至少绑定 `backup_id + family_id + lineage_id + imported_revision + 当前活动代`。同包重复导入且当前代与修订一致时直接显示已恢复。目标产生后续业务改动后，重新导入同包会显示此次整体回退的差异，取消则保留最新记录。

## 四天、五件物品的迁移验收

`fixtures/migration_roundtrip.json` 的 `domain_fixture` 是用合法领域命令建数的配方。仅用于测试家庭。构建完整快照时记录应用实际生成的 ID 和业务摘要，再用同一份备份做双端核对。

| 步骤 | 执行者与操作 | 可观察结果 |
|---|---|---|
| 建立样本 | Codex 在测试家庭选月牙耳兔。按夹具生成并确认 12 个挑战、3 个持续、2 个轻量成果，分布于四个实际日期。把第一天的持续投入作为两阶段项目第一阶段，项目第二阶段留待完成 | 17 条奖励，73 分，4 个成长日，已获得第 2 阶段。项目第一阶段已计在 17 条内 |
| 留下待办 | 再发布两项普通任务，一项保持待做，一项仅申报。选择扶手椅心愿，兑换四件 6 分装饰和 12 分围巾，穿围巾并把绿植摆到基础家园 | 余额 37，流水 22 条，拥有 5 件购买商品，1 个空间。连同项目第二阶段，共 2 个待做、1 个待确认 |
| 正向与反向 | 家长在飞行模式下从源设备导出迁移文件，经系统文件能力传到另一平台，目标预览、设新 PIN 并恢复。分别在独立基线家庭完成 iPad → 安卓与安卓 → iPad | 两方向各交付一次完整记录。目标显示相同伙伴、阶段、余额、待办、心愿、穿戴与摆放；规范化业务快照逐字段一致。源设备重启后保持只读 |
| 继续使用 | 在其中一次干净恢复后，对未变更的同包再导入一次，再由家长确认待确认的挑战任务，实际日期取夹具的第五天 | 重复恢复时仍为 37 分；新增确认后为 42 分，23 条流水、5 个成长日。源端继续显示 37 分 |
| 回退与分支 | 在上述目标再次选同包，先取消。再经家长明示确认、成功生成内部恢复点并完整覆盖 | 取消后 42 分，覆盖后 37 分；分支之间没有双倍物品。覆盖前的 42 分记录可通过内部恢复点核验 |

发布证据沿用 AC-21 至 AC-34、AC-38、AC-40。取证记录方向、设备、系统、构建号、备份格式、schema、恢复前后业务差异、源端冻结结果与重启结果。错误口令、磁盘不足、损坏文件、未来版本、保存回执未知和中途退出分别留存自动化结果。夹具数值与编解码向量已独立复算，原生 App 和跨端真机验收待实施。

在仓库根执行 `node tools/check_backup_vector.mjs` 可以用 Node 标准密码库独立复算固定向量。该命令已在准备阶段通过，Flutter 实现须用同一输入给出相同字节。
