# 0.21.2 系统文件往返迁移

使用 GitHub 下载分支的原签名安卓 **0.21.2+21**，构建提交为 `ae09472`。在 Android 9 软件模拟器的两个隔离用户中，全程启用飞行模式。安装件逐字节核对，迁移通过 App 的正常家长入口和 Android 系统文件界面完成。两端各自保存本地档案和家长凭据。[安装包与签名](../backup-export-performance/README.md) · [逐项数据核对](verification.json)

首端从系统文件选择器恢复合成档，余额 5 分，团团为 1 级、0 经验，奶油为 3 级、16 经验。含一件待确认小事、已解锁伙伴、衣饰、家居、心愿、剧情和回忆。首端在 Downloads 保存迁移档，选回同一文件验证，随后保持只读。第二端通过首次启动的恢复入口激活同档，生成独立设备身份。迁出前和恢复后 30 张业务表的摘要一致。[系统保存](a-to-b-system-save.png) · [App 回读](a-to-b-readback.png) · [第二端预览](target-compare.png)

第二端激活后，首端从家长入口归档。冷启动后仍为只读，归档前后的账本、伙伴、搭配和剧情摘要一致。Node 的 AES-GCM 与 Python 的 SQLite 独立读回了首程文件，另用 0.21.0 的 Flutter 读取器打开该档，两个读取结果都核对了原家园余额、经验和存档结构。[独立核对](verification.json)

第二端带团团回小家，确认一件待办，再踩过雨天地图的第二块石板。冷启动后余额为 7 分，团团为 1 级、1 经验，奶油为 3 级、16 经验，账本共 21 笔。第二端从系统文件界面保存并回读返程档，随后保持只读。独立解密的 30 张业务表与保存前一致，两份文件均通过 0.21.0 读取器的校验。[续走石板](target-rain-resumed.png) · [返程档回读](b-to-a-readback.png)

首端从「从外部备份恢复」打开返程文件，先生成 `ALICECP1` 内部恢复点，再确认替换和激活。冷启动后，用独立摘要核对首端的 30 张业务表与第二端迁出前一致。7 分、两只伙伴各自的等级和经验、第二块石板、衣饰和回忆随档恢复。原来 5 分的归档保留在原存储代。[恢复对照](return-compare.png) · [回迁后的伙伴](return-independent-progress.png)

这次使用安卓软件模拟器。实体 iPad 的系统文件、钥匙串、安装和双向真机迁移留在设备验收表。[设备验收](../device-acceptance/README.md)
