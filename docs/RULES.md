# 业务规则

开工基线 v1.1 · 2026-11-18。继承已讨论的单积分经济，并补充用户要求的完整离线、备份与迁移。数值在config/rules.json中镜像维护；本文件定义语义。任务内容一律由家长自定义。

## 任务与确认

| 编号 | 规则 |
|---|---|
| R-01 | 家长模式才能发布、确认、补录、扣分、纠错和导出/导入。儿童可以申报、兑换及布置。家长模式必须本地验证PIN，退出后台即锁定。 |
| R-02 | 三种类型：轻量行动2分、持续投入3分、突破挑战5分。任何任务内容都可由家长选择对应类型；不由App推荐内容或自动判定。 |
| R-03 | 发布时保存名称、内容、标准、类型、分值、日期和规则版本快照。后续改模板不回改已生成实例的承诺。 |
| R-04 | 执行方式为单次、重复、分阶段。重复按家长选定日期生成，每日/周期次数明确，默认每次计划生成一个实例。重复实例唯一键使用稳定模板ID、计划本地日期和序号；版本只作承诺快照，不参与重复身份。重启、日期回拨、修改模板都不能在已有计划槽位再次生成实例。 |
| R-05 | 项目每阶段独立选类型，按顺序确认；总预算为阶段之和。2+3+5的项目总发10分，整体完成不追加总奖励。阶段必须有独立标准，不能把同一成果重复奖励。 |
| R-06 | 实例状态为OPEN、SUBMITTED、RETURNED、APPROVED、EXPIRED、CANCELLED、CORRECTED。OPEN/RETURNED可申报；SUBMITTED由家长确认或退回；确认只结算一次。 |
| R-07 | 到期未申报的OPEN/RETURNED可标记EXPIRED；已经SUBMITTED的实例保持待确认。过期任务可由家长重开同一实例，避免重新创建引起重复结算。 |
| R-08 | 未完成、到期、取消或退回均不自动扣分。未预拆阶段的部分完成只保存过程，不能在确认时临时打折。已完成阶段不受后续暂停影响。 |
| R-09 | 家长可补录真实成果，必须填写标准、类型和实际发生日期；默认不能选择未来日期。备注可选。没有无来源手工赠分入口。 |
| R-10 | 申报不等于发分。确认时在一个本地事务内写入状态、完成记录、奖励流水、余额及必要成长记录；错误回滚全部。重复命令或同一实例再次确认返回既有结果，不再入账。 |

重复任务的暂停：停止未来新实例，保留已存在的任务与承诺；已生成且不再需要的实例由家长明确取消。模板改价与规则变更只影响后续尚不存在的计划槽位，取消的槽位也不自动重建。单次实例使用稳定独立ID，项目阶段使用项目实例ID与阶段ID组合。首版同一任务每日可配置1—5个实例，是防误操作边界，不要求孩子完成固定数量。

家长按当前设备确认时可看到实际发生日期。数据记录UTC时间和家庭本地日期，默认Asia/Shanghai；首次创建后首版不提供随意切换家庭时区的入口。设备时间异常只向家长提示，不制造额外奖励；离线环境不声称有可信服务器时钟。

## 积分与扣分

| 编号 | 规则 |
|---|---|
| R-11 | 初始积分为 0，基础家园与选定的首只伙伴免费。其他伙伴各花 30 分解锁。在已解锁的伙伴之间切换免费。只有家长确认的任务或阶段是正常发分来源。退款与撤销只冲回原操作。无第二货币、利息、到期清零或在线收益。 |
| R-12 | 流水追加保存，不直接改旧流水。余额等于所有实际有符号变动之和，且始终非负。任何结果都要同时保存来源、金额、操作标识及时间。 |
| R-13 | 扣分规则由家长提前定义具体行为、触发条件与1/2/3分档位。执行时填事实说明；同一事件只有一个扣分操作。默认每个结算日实际扣分总额最多3分。 |
| R-14 | 实扣=min(约定分值, 当前余额, 当日剩余扣分额度)。不足部分不欠账、不追扣。日额度按操作提交时的家庭日期计算，不能通过填写过去发生日期绕过；发生日期另行保留。 |
| R-15 | 撤销扣分只返还原实扣额，一笔只撤销一次。已占用的当日扣分额度不因撤销而重新释放，避免反复扣还。普通扣分不影响等级、物品或场景。 |
| R-16 | 误发奖励由家长更正：优先恢复相关误兑换，再撤回原奖励；若家长选择保留物品，则仅回收现有可用余额并明确记录无法追回的差额，不形成负数或未来债务。原任务置CORRECTED，不可再次确认；确需补正建立关联原记录的新任务。 |

R-16必须有预览：原发分、可回收金额、无法追回金额、拟保留物品。差额不是新奖励，只是家长明确接受的纠错损失；它不会再次计入预算或成长。不得后台静默处理。

一条已更正成果可关联一次补正。若补正记录还需调整，家长进入新记录进行更正，原奖励、追回金额和补正之间始终可追溯。

## 兑换与所有权

| 编号 | 规则 |
|---|---|
| R-17 | 商品采用固定价：小装饰6、配饰12、单件25、套装50、功能区90、店铺120。每周约30分只用于定价参照，不是必须完成的目标或拒付上限。 |
| R-18 | 商品ID与类型全局稳定，家庭拥有同一独有商品最多一次。每颗亲密度糖果单独兑换和保存。套装内部物品不另售；不得将已售单件又作为套装必付内容。功能区/店铺含完整基础布置。 |
| R-19 | 购买必须足额；在一个事务中扣分、写流水、写购买及所有权。任一步失败全部回滚；不允许界面先宣布成功再补扣。 |
| R-20 | 儿童误购后 5 分钟内可撤销，家长可随时处理误购。只退原实付积分一次并收回对应物品、容器或未喂食的糖果。容器里另购的物品返回物品栏。伙伴兑换确认后永久解锁，已喂食的糖果完成消费。 |
| R-21 | 已有物品换装、摆放、收回和正常换色免费；收回只回物品栏，不返钱。无出售套利、耗损、租金、饲料或体力消费。 |
| R-22 | 首版目录价格固定，不提供家长随手改价功能。将来升级价格时，已有心愿保存选定时价格，新旧价格取较低值；不因余额增加涨价。 |

功能区与店铺附带的基础物品绑定该空间，固定呈现在该空间；退还空间时一并收回。套装按设计成组呈现；旧存档中已分放的部件仍归各自空间，退还套装时全部收回。所有组件均关联原购买ID，不能单独退款。

退款依靠持久化购买ID与唯一冲回记录；改系统时间不延长儿童可撤销窗口，可使用同会话单调时钟，重启后若无法可靠确认窗口则提供家长退款入口。所有积分操作都不产生随机回报。

预算显示当前家长安排下可获得的最大值，只计算明确次数和本周期阶段。高于每周参照的两倍时只在家长发布页面提示；不阻止发布，不截断已承诺奖励，不增加儿童的任务压力。

## 成长与空间

每只伙伴独立从 1 级、0 经验起步，第 2 到第 6 级分别需要累计 3、10、20、35、55 经验。0.20 及更早的旧档升级时，把原有经验和已获得的最高阶段交给存档中的当前伙伴。原有搭配与回忆继续保存，其他伙伴可用积分解锁。

每只伙伴独立从 0 亲密度起步。按家庭日期，摸摸与呼唤当天各首次增加 1。亲密阶段门槛为 0 初见、1 熟悉、2 默契、8 相伴、20 挚友。升级旧档时，已拥有伙伴的每条首次互动回忆各作为 1 点起始亲密度。

每颗亲密度糖果花费 3 家庭积分，可多次兑换。糖果保存在家庭内，确认喂给当前伙伴后消耗一颗，并为该伙伴增加 3 亲密度。喂食不另扣积分，糖果和互动均不影响经验与进化等级。未喂食的糖果可按 R-20 退款。更正成果时，可选择收回相关未喂食糖果以追回原积分。

| 编号 | 规则 |
|---|---|
| R-23 | 每件家长确认的有效现实成果给确认当时正在陪伴的伙伴增加 1 经验。切换、互动、预览、消费及普通扣分的经验增量均为零。 |
| R-24 | 同一天的不同成果分别计经验，阶段项目仅计已完整确认的阶段。补录适用同一规则。操作重试仍只计算原实例一次，实际日期供手记回顾。 |
| R-25 | 更正时从原先获得经验的伙伴扣回这条成果的 1 经验。该伙伴已获得的等级与外观保留。普通扣分、消费或休息均保留等级与经验。 |
| R-26 | 每种配饰/衣服占一个明确槽位，按伙伴保存搭配；同一件已拥有的衣饰可免费用于三只伙伴各自的搭配。当前仅展示一只。子项保留原购买归属。家具按所属空间和固定画位呈现；旧版保存的空间归属仍然有效，同一件家具只出现在一个空间。场景与店铺无收入、订单或维护周期。 |

成长日期不是货币；不建立可转账经验值、能力排名或行为类别评分。v1不预设阅读、家务等内容类别或对应成就；成长记录直接保存家庭实际填写的任务与反馈。

## 离线、备份与迁移

| 编号 | 规则 |
|---|---|
| R-27 | 安装包内含所有初版素材。首次初始化、任务、确认、计分、兑换、成长、布置、备份、恢复全部可离线完成，无后台服务依赖。 |
| R-28 | 加密 `.alicebackup` 包含家庭、任务历史、流水、余额、物品、布局、心愿、规则和目录版本，以及当前伙伴、已解锁伙伴、各自搭配、成长、亲密度和糖果。旧设备 PIN 和密钥留在本机。 |
| R-29 | 导出采用一致性快照；写文件中断只留下可清理的临时文件。系统文件选择器取消或空间不足，不能提示导出成功；当前数据不变。 |
| R-30 | 恢复先解密、校验、预览，再经家长确认完整替换。当前非空数据须先生成恢复前副本。错误口令、损坏、未知未来版本、缺少必要素材或校验失败均不得修改当前数据。 |
| R-31 | 恢复复制整套状态，不把备份余额当成新增奖励。旧备份会回退到其时间点，必须预览并确认；不合并两个账本。同一个备份的重复导入不能导致加分或重复物品。 |
| R-32 | 迁移包与备份包同格式，mode不同。迁移导出期间暂停写入，成功后源设备保持只读待迁移；确定失败恢复原可写状态，系统保存回执未知则保持只读待验证。目标先准备新device_id和家长凭据，再激活已校验的数据代成为当前使用设备。 |
| R-33 | 目标导入不会自动删除源数据。源设备只读状态由家长在确认目标成功后归档；若确定目标未继续使用，可取消迁移恢复源写入。离线无法防止用户故意克隆备份，单一当前设备是明确的使用约定，不宣称跨设备强一致。 |
| R-34 | App私有目录内保留最多5个自动恢复点，用于升级、导入和大范围纠错前；它们不替代用户导出的外部备份。首版无联网自动备份，也不自动把文件上传云端。 |
| R-35 | 备份口令至少10个Unicode码点，不得直接采用家长的6位PIN；不自动保存口令。忘记口令无法解密已有备份；当前原设备仍可用时可重新导出并设置新口令。 |

家长PIN丢失使用初始化时生成的本地恢复密钥重设；两者都丢失时只能从能解密的外部备份恢复或明确清空重建。新设备恢复时重新设置PIN与恢复密钥。不要设计通用默认PIN或隐藏后门。
