### 小家画面与剧情验收

0.14.1 的庭院与第一阶段团团是下一轮的“修改前”。团队在日常小家入口操作，固定机位、伙伴阶段、搭配、目标点、触发顺序和取帧间隔，录修改前后全景与同一地面局部。独立试玩者先以正常速度、静音观看，再逐帧核对。下面的项目随对应开发阶段执行。[基线录像与实测口径](evidence/courtyard-motion/README.md) · [开发顺序](PLAN.md#当前开发顺序)

| 要验的体验 | 怎样判断 |
|---|---|
| 庭院有风、木梯稳固 | 同镜头观察上、中、下三处踏板和平台栏杆。沿用 125 帧对照，并在独立背景上复查木梯矩形，踏板边缘位置固定。梯上叶簇和树冠都要看得到自然摆动。 |
| 幼猫真正走到目的地 | 点地、「过来」、自主走动各录完整的起身、迈步、落地和收步。看重心越过支撑爪，步频随实际前进速度变化；短程、长程、斜向、接近纵向、中途改向及被摸停都能从当前姿态衔接。看不清哪只爪在承重或原速可见滑行，即退回动画复做。 |
| 承重爪在地面上的位置 | 为每只可见承重爪标出落地至离地的整段，在无损画面中跟踪真实爪垫相对于固定草地的位置。报告它到初次落地点的最大二维偏移，同时核对运行时标记。建议内部回归线为归一到 960 像素宽的同机位画面后，每段最大偏移 ≤2 像素；该值是本轮工程目标。0.14.1 测得的 6.9、13.8、10.0 像素是低位白爪的相邻帧横移，不能直接用于新旧承重误差比较。 |
| 穿戴和家具属于同一幅画 | 幼猫原装、外套、围裙与头、脸、颈槽的 36 种合法组合先查资源与映射。分别在试穿、已穿、行走和转身时看帽檐、耳根、镜腿、围巾下缘；注明人工复看的组合。以浅色和深色背景放大查毛边，在实际大小查笔触、遮挡和受光。每件家具在所属房间比兑换前后及重启画面，落地有接触影，窗花由窗棂遮住、窗光落在对应木板上。 |
| 互动、技能、进化和界面 | 面向本批交付的物种和阶段，正常速度下看清朝向玩家、动作发力、结果与收势。关掉声音和特效仍能辨认主体动作，减少动态或跳过仍得到相同结果。小屏和 iPad 横竖屏上，主要操作和放大文字均可达，控件给爪部、脸和当下的剧情线索留出空间。 |
| 数学是剧情中的行动 | 从「小家 → 主线」进入，孩子能看懂谁需要帮助、要解决什么数量关系。尝试一次未达条件的操作，再完成正确操作，看伙伴或场景给出不同且对应的回应。退出重进能从书签继续，重玩后家里保留结局。核对前后积分、经验和物品所有权。 |

每项记录具体版本、设备或渲染环境、操作、录像时刻和观察到的缺陷。自动化功能检查、独立视觉复核、实体设备结果与家长体验分别记状态。缺画或穿帮附对应姿态并返工，已购搭配等相关路径齐备后才将该范围列为家庭更新的完成项。实体机用 profile 模式连续走动、转向、换装，记录刷新率、帧耗时 p95/p99、超出一帧预算的次数与峰值内存，和同机基线比较。触摸手感与双向迁移在对应设备上实测。[双端验收记录](evidence/acceptance.csv)

## 证据与发布条件

每条记录：AC编号、实际状态、源码commit、包/数据库版本、设备型号与系统、时间、步骤、结果、日志/截图/录屏路径。不存在的证据不能留一个假链接。

自动规则和仓储测试先运行，随后integration_test，最后真实设备与文件系统操作。模拟器、桌面预览和同平台导入测试不能替代AC-29/30/41。没有设备或签名环境则BLOCKED，不是PASS。

发布必需项不得有FAIL、NOT_RUN或BLOCKED。若用户选择先验收部分平台，应记录明确的分批范围，不能将部分交付标为完整双端完成。
