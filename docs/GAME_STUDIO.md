# 银杏家园游戏制作组

这是一套仓库内的 Codex 分工。制作人由主会话担任，家长保留最终成品验收权。当前在前期讨论阶段，首段样片是提案，复工以家长下一次指示为准。

沿用已确认的 C 版水粉笔触、银杏家园和三宠六阶段。用家长提到的《Pokémon Friends》讨论触摸后的表演节奏与陪伴感，银杏家园的原画和角色设定继续作为制作依据。

## 为什么需要分工

0.13 的账本与存档已有技术证据。家长试玩提出的配饰、表演、剧情与修窗成画仍需返工。本轮由一名美术与动画审阅者、一名叙事与声音审阅者分别复核了既有代码和画面。

| 家长看到的现象 | 在 0.13 中找到的原因 | 下次怎样亲眼检验 |
|---|---|---|
| 围巾和头饰像贴上去的 | 原画上按锚点旋转、缩放配饰，再截取部分下巴覆盖围巾。眼镜用曲线画在眼位上。试戴和保存成功，仍可能缺少毛发遮挡和投影。[穿戴合成](../apps/mobile/lib/illustration/tailoring.dart#L175) · [衣橱实拍](evidence/daily/phone-accessories.jpg) | 看同一只桃桃转头、低头时，近侧颈毛盖住布边，围巾压出的褶皱、阴影随肩颈变化。 |
| 场景在晃，伙伴缺少表演 | 腾跃用常态图和腾空图淡入淡出，再移动角色。部分树叶和水面由底画网格按周期变形。两幅姿态之间的受力过程很难读出。[腾跃绘制](../apps/mobile/lib/illustration/puppet.dart#L439) · [背景网格](../apps/mobile/lib/illustration/animated_backdrop.dart#L151) | 固定机位、关闭粒子，原速看清桃桃听风转耳、前爪压围巾、移重心推篮、松爪回弹。能跟着同一片叶子从窗缝落到地上。 |

小项目最容易返工的地方是几个人交接的同一个镜头。多开岗位也会带来画风漂移、分镜版本对不上的成本。制作人按镜头调用专长，通常同时开两到三个岗位即可。每个岗位都以同一段可玩的场景为交付依据。

## 怎样开一次工

1. **制作人发一张镜头单。** 写清玩家会看到什么、能做什么、操作后发生什么，附 C 版原画、涉及的伙伴与成长阶段、目标屏幕、交付物和负责人。第一次只需剧情与美术共定镜头。
2. **美术和动画共看同一张画。** 编剧交有因果的分镜，美术在手机大小上给出穿戴与房间成画，动画给出静音原速小样。退修时指出具体姿态或画面。镜头定时后再约声音，工程同步核对原游戏入口和存档状态。
3. **一人负责集成。** 发任务时带上相同基线提交与各自可写的路径。并行写文件各用独立 Git 工作树。美术、动画和声音交源件及导出件，工程负责 `apps/mobile`、公共素材清单与存档接口。制作人归并已审的版本。只读走查可共用同一份检出。
4. **从手机上的小家开始试玩。** 交同一构建的原速连续录屏、定格与操作前后状态。评审先描述实际所见，再对照故事。穿帮交回美术或动画，动机与操作脱节交回编剧，落位与存档错误交回工程。模拟器或低采样录像要标明，尚未观察到的行为记作待验证。

交接只需留下镜头/版本、输入依据、输出位置、下一位要接什么、已验证和仍缺什么。制作人负责同岗位间的取舍。若美术与工程意见相左，在同一机位比较完整成画和实际手机帧再决定。日常单一修复可由一个岗位完成。

## 建议的第一段样片 · 风过暖廊

**目的**　在一次约一分钟的试玩内，一起检验穿戴、角色表演、场景光影以及数学能不能推动故事。取第三阶段桃桃、一条围巾、一间暖廊，奶油只在窗外石桥和结尾露面。其余伙伴、阶段与商品等样片定型后展开。以下是复工提案。

| 镜头里发生什么 | Alice 能做什么 | 画面和声音如何回应 |
|---|---|---|
| 风从窗缝进来，一片叶子落到地上。桃桃先朝风声转耳，再低头用爪压住围巾，把叶篮推给 Alice。奶油停在光纹断开的桥上。 | 看见三扇窗每扇四格，已有 4、3、0 片，可以先看任意一扇。 | 窗框和机位稳住，叶片从窗到地有连贯轨迹，爪压上去的那一刻，围巾折起一角。风声和摩擦声各有可见来源。 |
| 从奶油所在一侧往暖廊看，桥上有三段光路。第一段已亮，第二扇窗缺一片，第三扇缺四片。 | 点篮取叶，再点实际窗格嵌进去。先补哪扇都可以。 | 每片落位有短促的扣合声。先补第三扇，远处桥段亮起，奶油转头看光，仍在第二段缺口等。先补第二扇，奶油可以走到第三段前。 |
| 五片补齐，桃桃松开围巾，奶油沿亮起的路进门。 | 回暖廊自己看一眼，也可以稍后重开。 | 玻璃透光、窗框遮挡、家具与地板接光来自同机位修复后的场景画。先闻脚步再见奶油。静音也能看到它回来，重开仍是修好的暖廊。 |

第一次内部评审一起看穿戴及窗光定稿、关特效的连续表演，以及从原游戏入口操作到团聚的原速试玩。固定手机机位、静音，分别按两种补窗顺序走一遍。让第一次见这段戏的人说说“桃桃为什么推篮子”“你补了哪里”“奶油为什么停下、又为什么走了过来”。记录实际回答，家长保留最终判断。试玩、重玩与修窗均为零积分、零经验。

现有仓库保存了 WebP 角色和设定板，跟踪文件中未找到 PSD、Krita 分层画稿或 Cubism 模型。美术需要为这段表演补出转面和遮挡源稿。先用手绘关键帧解决受力，再按这段表演的轮廓、遮挡、成本和手机表现决定是否采用 Live2D。音效先服务于动作，完整配乐和全程配音排在镜头定型之后。

## 在 Codex 中使用

岗位已经登记在项目的 [Codex 配置](../.codex/config.toml)。在支持项目角色的已信任 Codex 会话中，由制作人按上表中的英文岗位名委派。在只能给子 Agent 发任务文字的云会话中，制作人运行下列命令取得同一份岗位指令，把它与镜头单交给对应子 Agent。岗位说明随仓库维护，家长用中文说目标即可。

```sh
python3 tools/studio_roles.py
python3 tools/studio_roles.py --brief story_gameplay
```

例如，家长说“按游戏制作组评审风过暖廊，只做分镜”。制作人调用剧情与美术，收回同一机位的答复后交独立试玩岗指出还缺哪些可观察的事件。若客户端无法启动子 Agent，制作人注明实际执行方式，独立试玩留到有人能独立承担时。

本次实际演练了岗位交接。两位审阅者分别走查旧版美术动画和剧情声音，第三位独立试玩者按 `playtest` 岗位先看旧包截图，指出初稿里“先补远窗，奶油也会向前走”的因果错误。上面的分镜已据此调整。新样片的制作、声音试听、手机试玩与家庭验收仍待复工。
